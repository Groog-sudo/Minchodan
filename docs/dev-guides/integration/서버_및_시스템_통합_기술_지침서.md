# Minchodan 네비게이션 백엔드 시스템 통합(Integration) 기술 지침서

> **작성일**: 2026-07-08
> **버전**: v2.3.0 (2026-07-11 kb 정합화: §3.2 GPS 수신을 실제 구현인 `realtime_gps` 전용 메시지 기준으로 정정, §3.3에 GPS 수신 시점 직접 평가 경로 추가, §3.4 nav_route 지도 경로 전송 신설, 로컬 절대 경로를 저장소 상대 경로로 교체)
> **독자**: 백엔드 개발자 및 시스템 엔지니어

본 문서는 실시간 길안내(네비게이션) 서비스를 메인 백엔드 서버에 마운트하고, Tailscale 사설망으로 외부 실제 단말(iOS) 및 관제 화면과 통신을 비침습적으로 연동하기 위한 백엔드 기술 지침서입니다.

---

## 1. 모듈 파일 배치 및 단일 포트(8000) 통합 구동

네비게이션 모듈은 별도의 8001번 독립 포트를 사용하지 않고, 기존 Minchodan 메인 서버(8000 포트)에 **서브앱(Sub-app)**으로 마운트되어 통합 구동됩니다.
* **배치 경로**: `server/navigation/` (프로젝트 루트 기준)
* **FastAPI 통합 마운트 구현**:
  * 메인 서버 entrypoint(예: `server/main.py`) 내부에서 아래와 같이 네비게이션 서브앱을 마운트하여 단일 포트 8000번 하위의 `/navigation` 경로로 통합 제공합니다.
  ```python
  from fastapi import FastAPI
  from server.navigation.server import app as navigation_app

  app = FastAPI()
  # 8000번 포트 하위에 네비게이션 서브앱 마운트
  app.mount("/navigation", navigation_app)
  ```

---

## 2. Tailscale을 이용한 통신 채널 개방

실기기(iOS 앱) 테스트 환경 및 야외 현장 도보 실측을 지원하기 위해, 서버와 단말을 같은 tailnet에 연결합니다.
* **서버 Tailscale 주소 확인**:
  ```bash
  tailscale ip -4
  ```
* **Tailscale 주소 적용 예시**:
  * **API 및 지도 웹페이지 주소**: `http://[SERVER_TAILSCALE_IP_OR_MAGICDNS]:8000/navigation/`
  * **지도 웹페이지 전용 웹소켓 주소**: `ws://[SERVER_TAILSCALE_IP_OR_MAGICDNS]:8000/navigation/ws`
  * **주의**: 위 `/navigation/ws`는 지도 웹페이지(서브앱) 전용 채널이다. 단말(iOS 앱)의 GPS·프레임·STT 통신은 별도의 메인 채널 `ws://[SERVER_TAILSCALE_IP_OR_MAGICDNS]:8000/ws/detect`를 사용한다.

## 3. 핵심 백엔드 소스코드 수정 및 연동 규격

### 3.1. `server/stt/stt_to_llm_bridge.py`
* **목적**: 마이크 음성 인식(STT) 명령어 분류 및 네비게이션 상태(IDLE ➔ WAITING ➔ NAVIGATING) 제어.
* **구현**:
  * `"네비게이션 켜줘"` 등의 명령 감지 시 대기 상태 전환 및 목적지 유도 응답 발화. 목적지 명사 셋업 시 TMAP 경로 조회를 거쳐 안내 중 상태로 진입.
  * **2026-07-10 확장**: `"길댕아"` 2단계 웨이크워드(편집거리 1 이하 퍼지 매칭)와 자유 질의응답 모드가 추가됨. 상세 명령 어휘는 [`docs/design/api_specification.md`](../../design/api_specification.md) §6.3 참조.

### 3.2. `server/api/ws_router.py`
* **목적**: 단말기로부터 전달받은 GPS 데이터의 실시간 수집 및 전파.
* **구현**:
  * **2026-07-10 정정**: GPS는 `detection` 페이로드의 필드가 아니라 **별도 `realtime_gps` 전용 메시지 타입**(`{type:"realtime_gps", lat, lon, heading}`)으로 수신하며, `NavigationManager.update_gps`로 연계한다(fire-and-forget). 상세 규격은 api_specification §6.5.
  * **2026-07-11 추가**: NAVIGATING 상태이면 `realtime_gps` 수신 시점에 `get_combined_guidance`를 직접 평가하고 `_send_nav_guidance()`로 TTS 합성·전송한다. 기존 §3.3(consumer) 경로만으로는 카메라 탐지가 없는 빈 장면에서 길안내가 전혀 발화되지 않는 무음 결함이 있었다(실기기 실측). 중복 발화는 nav_filter의 announced_cache/silence_interval이 양쪽 경로 공용으로 차단한다.

### 3.3. `server/detection/consumer.py`
* **목적**: 객체 탐지 최종 가이드 송출 전 네비게이션 멘트 주입.
* **구현**:
  * `_send_cognitive_guide`에서 오케스트레이터 호출 직전 `NavigationManager.get_combined_guidance`를 조회해 현재 위치의 보행자 방향 전환 가이드를 획득하고, 이를 기존 YOLO 인지 가이드 문장에 주입.
  * **비협상 원칙**: 네비게이션 멘트는 인지 경로(guide)에만 주입되며, 반사 경로(reflex_alert, 사전합성 클립)에는 어떤 경우에도 결합되지 않는다.

### 3.4. nav_route 지도 경로 전송 (2026-07-11 신설)
* **목적**: 단말 하단 T맵 지도 패널(`client/src/components/NavMapPanel.tsx`, 운영자/데모용)에 경로 폴리라인 좌표 전달.
* **구현**:
  * 경로 수립/해제/WS 재접속 복원 시 `nav_route` 메시지(좌표 목록 + `TMAP_APP_KEY`)를 전송한다. 상세 규격은 api_specification §6.6.

## 4. 백엔드 시스템 기동 및 검증 순서

1. **기존 도커 및 로컬 서버 실행** (8000 포트 단일 구동):
   ```bash
   .\venv\Scripts\python.exe server/main.py
   ```
2. **Tailscale 연결 확인**:
   ```bash
   tailscale status
   ```
3. 아이폰의 웹소켓 연결이 `ws://[SERVER_TAILSCALE_IP_OR_MAGICDNS]:8000/ws/detect`를 통해 안정적으로 도커/로컬 백엔드로 인입되는지 로그를 통해 확인합니다.
