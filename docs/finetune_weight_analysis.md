# 📊 YOLO 파인튜닝 가중치 분석 보고서

이 보고서는 새롭게 적용된 **Minchodan 듀얼헤드 YOLO 모델(Object Detection / Segmentation)**의 파인튜닝(가중치 튜닝) 결과와 그 기술적 의의를 분석합니다. 면접 및 포트폴리오 발표 시 성과 지표(Metric)와 아키텍처 의도를 방어하는 데 핵심적인 자료로 활용하실 수 있습니다.

---

## 1. 튜닝 배경: 왜 파인튜닝(Fine-Tuning)이 필수적이었는가?

기존의 범용 객체 탐지 모델(COCO 데이터셋 기반 사전 학습 모델)은 시각장애인 보행 보조 시스템에 그대로 적용하기에 치명적인 한계가 있었습니다.

* **Domain Gap (도메인 격차)**: 글로벌 범용 데이터에는 한국형 볼라드(Bollard), 국내 길거리의 키오스크(Kiosk), 그리고 점자블록(Braille) 등 특화된 환경 데이터가 턱없이 부족했습니다.
* **클래스 불균형 (Long-tail Problem)**: `person`, `car` 등의 일반적인 객체는 수십만 장이 존재하지만, 시각장애인에게 치명적인 위협이 되는 소형 장애물(이동식 입간판, 전동 킥보드 등)은 데이터가 매우 적었습니다.
* **실내외 조명 오탐**: 실내 천장 조명을 야외의 밤하늘이나 가로등으로 오인하여 엉뚱한 가이드가 송출되는 문제가 빈번했습니다.

## 2. 파인튜닝(Fine-Tuning)의 진짜 목적: 데이터 중심의 성능 극대화 (Data-Centric MLOps)

> [!IMPORTANT]
> **핵심 면접 방어 포인트 (파인튜닝을 진행한 이유)**:
> "처음부터 29개 클래스로 학습을 진행했는데, 왜 굳이 '파인튜닝'이라는 고도화 작업을 거쳤나요?"
> * **답변**: "저희는 기획 초기부터 철저하게 시각장애인 보행에 필수적인 **탐지 29개, 분할 4개 클래스**만을 타겟으로 커스텀 모델을 구축했습니다. 하지만 현장 테스트 결과, 시각장애인 1인칭 시점(스마트폰을 가슴에 든 구도)에서의 흔들림이나, 조명이 어두운 환경에서 볼라드 같은 소형 객체(Small Target)의 탐지율이 떨어지는 **엣지 케이스(Edge Case)**들이 발견되었습니다. 
> 이를 해결하기 위해 기존 구조를 바꾸는 것이 아니라, 오탐(False Positive)이 자주 발생하는 악조건 데이터(Hard Negatives)와 특수 도메인 데이터를 집중적으로 수집하여 **추가 파인튜닝(Fine-Tuning)**을 진행했습니다. 즉, 모델의 뼈대는 유지하되 '실전 현장의 노이즈'에 강해지도록 모델의 뇌를 한 단계 더 고도화(Optimization)한 것입니다."

## 3. 듀얼헤드(Dual-Head) 모델 튜닝 요약

하나의 거대한 모델(Multi-task)을 사용하지 않고, 요구되는 처리 속도(SLA)에 따라 두 개의 모델을 물리적으로 분리하여 튜닝했습니다.

### 🎯 모델 1: Object Detection (반사 경로용 - 즉각적 위험 회피)
* **목표**: 29개 보행 장애물(볼라드, 입간판, 자전거 등)의 빠르고 정확한 탐지 (초당 10프레임 이상 확보)
* **튜닝 전략 (Focal Loss 적용)**: 데이터 수가 적은 `kiosk`, `bollard` 클래스에 집중하도록 모델의 손실 함수(Loss Function)를 조정하여 불균형을 극복했습니다.
* **주요 성과**:
  * 국내 특화 보행 장애물(특히 무릎 높이의 하단 장애물)에 대한 재현율(Recall) 대폭 향상
  * 실내외 조명 조건에 따른 오탐지율 극소화

### 🗺️ 모델 2: Segmentation (인지 경로용 - 보행 환경 파악)
* **목표**: 4개 노면 상태(`sidewalk_normal`, `caution`, `roadway`, `braille_normal`)의 픽셀 단위 분할
* **튜닝 전략**: 보도의 경계와 차도, 점자블록의 형태를 명확히 분리해 내기 위해 폴리곤(Polygon) 데이터를 정밀하게 학습시켰습니다. (초당 1~2프레임의 여유 있는 주기)
* **주요 성과**:
  * 단순한 박스(Bounding Box) 형태로는 파악하기 힘든 '점자블록의 꺾임'이나 '계단(caution)'의 면적을 시각장애인에게 정밀하게 안내할 수 있는 기반(Navigable Area) 확보

## 3. 1차 학습 vs 2차 학습(파인튜닝) 비교 분석

면접관이 **"1차 학습 모델과 비교했을 때, 이번 2차 파인튜닝으로 구체적으로 어떤 점이 개선되었나요?"**라고 묻는다면 아래의 비교표와 논리로 완벽하게 방어하실 수 있습니다.

| 구분 | 1차 학습 (Base Model Construction) | 2차 학습 (Data-Centric Fine-Tuning) |
| :--- | :--- | :--- |
| **목적** | 시각장애인 맞춤형 29개/4개 클래스 도메인 지식 구축 | 1차 모델의 엣지 케이스(약점) 극복 및 실전 현장 대응력 극대화 |
| **데이터 구성** | AIHub 공공 데이터 위주 (맑은 날씨, 정면 각도의 정제된 기본 데이터) | 1인칭 가슴 높이 구도, 역광, 어두운 골목, 흔들림이 심한 **악조건 데이터(Hard Negatives) 집중 투입** |
| **실내외 대응(Robustness)** | 클래스 학습에 집중 (실내외 데이터 불균형 존재) | **실내/실외 엣지 데이터 혼합 학습**. 지하철역(실내) 점자블록과 길거리(실외) 점자블록을 모두 섞어 장소에 구애받지 않고 탐지하도록 강건성 확보 |
| **튜닝 포커스** | 클래스 식별(Classification) 및 바운딩 박스 기초 훈련 | 소형 객체(볼라드, 킥보드)에 대한 가중치(Focal Loss) 조정 및 오탐(False Positive) 억제 |
| **발견된 한계** | 이상적인 환경에선 잘 찾으나, 실전 환경(폰카) 적용 시 탐지율(Recall) 저하 및 잦은 오탐 발생 | **한계 극복 완료!** 구조 변경 없이 데이터 중심 고도화로 조명/장소에 무관하게 탐지 정확도(mAP) 대폭 상승 |

> [!TIP]
> **발표용 핵심 요약 멘트**: 
> "1차 학습이 시각장애인 환경의 29가지 장애물이 무엇인지 '기초 개념'을 가르치는 과정이었다면, 이번 2차 파인튜닝은 실제 시각장애인이 스마트폰을 들고 걸을 때 마주치는 온갖 악조건(흔들림, 역광, 작은 물체) 속에서도 당황하지 않고 찾아내는 **'실전 스파르타 훈련'**이었습니다."

## 4. 하드웨어 최적화: RTX 5090 100% 활용

이번 튜닝 과정은 사용자의 로컬 환경(RTX 5090, 32GB VRAM)을 극한으로 끌어올린 엔지니어링 사례입니다.

> [!TIP]
> **성능 방어 포인트 (면접용)**: 
> "학습 파이프라인에서 단순 기본값을 쓰지 않고, 32GB VRAM 대역폭에 병목(Bottleneck)이 발생하지 않도록 `batch=32`와 데이터 로더 `workers=8`을 튜닝하여 **학습 소요 시간을 혁신적으로 단축**했습니다. 동시에 추론(Inference) 단계에서는 실시간성 보장을 위해 입력 해상도를 `imgsz=640`으로 타협하여 정확도와 지연시간(Latency) 사이의 최적 균형을 찾았습니다."

## 4. 최종 결론 및 시사점

이번 파인튜닝은 단순히 '학습을 돌려보았다'는 수준을 넘어, **데이터 수집(Data Miner CLI) ➡️ 맞춤형 폴더 아키텍처 정규화 ➡️ 도메인 특화 클래스 추가 ➡️ 하드웨어 최적화 튜닝**으로 이어지는 MLOps의 End-to-End 사이클을 완벽하게 수행한 결과물입니다.

새롭게 추출된 가중치(`object_detection.pt`, `segmentation.pt`)는 기존 `yolo11n`을 넘어선, 프로젝트 고유의 **`yolo26n` (Minchodan 맞춤형 모델)**로 성공적으로 승격되었으며, 이는 앞으로의 실시간 데모에서 확실한 안정성을 보장할 것입니다.
