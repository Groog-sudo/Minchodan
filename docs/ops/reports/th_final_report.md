## 1. 프로젝트 개요

### 프로젝트명
Gildang(길댕) — 시각장애인 보행 보조 스마트 가이드독 AI 플랫폼

### 프로젝트 주제 및 개발 목적
시각장애인이 스마트폰 카메라만으로 보행 중 주변 장애물과 노면 상태를 실시간 인식하고, **음성과 햅틱(진동)** 으로 즉시 안내받도록 하는 것이 목적입니다. 핵심 설계 원칙은 **이중 경로의 물리적 분리**입니다.
- **반사 경로(Reflex)**: 정면 근접 고위험 상황을 즉시 경보. LLM/RAG/실시간 TTS를 절대 경유하지 않고 **사전 합성된 고정 음성 클립**을 선점 재생합니다. 목표 지연 300ms 이내.
- **인지 경로(Cognitive)**: 중·저위험 상황에 대해 RAG로 대처 수칙을 검색하고 LLM으로 상세 가이드 문장을 생성해 안내합니다.
이 분리는 "안전 경보가 무거운 AI 추론 때문에 지연되면 안 된다"는 안전 요구를 코드 구조 자체로 강제한 것입니다.

### 주요 사용자 또는 활용 대상
| 대상 | 상호작용 방식 |
|---|---|
| **시각장애인 종단 사용자** | 음성·햅틱만으로 상호작용(화면 미사용) |
| **운영자/보호자** | React 운영 콘솔로 실시간 탐지 피드·위험 이벤트 로그·세션 상태 모니터링 |

## 2. 본인의 핵심 담당 역할 및 기여도 (정량적 성과 포함)

이번 프로젝트에서 저의 주된 기여는 **데이터 전처리와 대규모 모델 학습 파이프라인 최적화**, **생활지원 RAG 데이터베이스 셋업 및 LLM 폴백 구축**, 그리고 **운영자 관제 콘솔의 통신 안정성(JWT 인증 방어) 확보**입니다.

### 2-A. YOLO Segmentation 모델 파인튜닝 및 학습 데이터 파이프라인 (핵심)
- **불균형 클래스 완화 및 FiftyOne API 마이닝**: 학습 데이터 내 특정 소수 객체(전동킥보드, 볼라드 등)의 데이터 부족으로 인한 클래스 불균형(Class Imbalance) 문제를 해결하기 위해, **FiftyOne API를 연동하여 소수 클래스 데이터를 집중적으로 마이닝하고 보강**했습니다. 이를 통해 파인튜닝 모델의 편향 및 미탐지 문제를 선제적으로 튜닝하여 전체 객체 mAP(Mean Average Precision) 신뢰도를 확보했습니다.
- **46,000장 폴리곤 데이터 정규화**: AI Hub 서피스마스킹 XML 폴리곤 데이터 4.6만 장을 YOLO 포맷으로 파싱 및 변환하는 스크립트를 직접 개발. 6개의 원본 라벨을 4개의 주요 학습 라벨(보도, 주의구간, 차도, 점자블록)로 정규화 매핑 완료.
- **35만 장 기반 풀 학습 최적화**: RTX 5090 (VRAM 32GB) 딥러닝 팜을 극한으로 활용하기 위해 `amp=True`, `cache='disk'`, `batch=-1(auto)` 설정을 자동 주입. 메모리 누수 없이 **100 Epoch 풀 학습**을 단기간 내 안정적으로 성공시킴. (약 6.5MB의 `best.pt` 도출)
- **가중치 관리 자동화**: 매 학습 완료 시 산출된 가중치 파일에 `YYYYMMDD` 날짜 스탬프를 자동 부착하고, 디스크 용량 관리를 위해 10개의 대표 샘플 외 `last*.pt` 파일들을 자동 삭제(`cleanup_datasets.py`)하여 팀원들의 개발 편의성을 대폭 향상.

### 2-B. RAG 더미데이터 시딩 및 생활지원 LLM 고도화 (핵심)
- **41종의 실용적 시나리오 DB 구축**: 복지카드 발급, 안내견 출입 거부 대처, 맹학교 정보 등 실생활 밀착형 시나리오 41종을 수집하여 ChromaDB 기반 벡터 더미데이터 셋업.
- **Ollama ↔ Gemini API 무중단 핫스왑**: Ollama(`bge-m3`) 로컬 LLM이 오프라인 또는 추론 실패 시, 즉시 `Gemini API (gemini-2.5-flash-lite)`로 폴백(Fallback)하도록 설계하여 장애 없는 응답성 보장.
- **응답 품질 가드레일**: `GEMINI_MAX_OUTPUT_TOKENS` 옵션으로 출력 길이를 180 토큰 내외로 억제해 과도한 환각(Hallucination) 방지. 마크다운(`**`) 및 목록 기호를 `sanitize` 처리하여 TTS가 기계적인 기호를 소리 내 읽는 치명적 UX 결함을 차단(최대 2문장 제한).

### 2-C. 운영 콘솔 프론트엔드 연동 및 JWT 401 에러 스팸 방어 (핵심)
- **초당 수십 건의 401 API 에러 스팸 완전 차단**: 브라우저 `localStorage`에 만료된 JWT가 남아있을 경우 백그라운드의 SSE(`useMonitorStream.ts`)와 로그 폴링이 계속 돌면서 **서버 측에 초당 수십 건 이상의 401 에러 로그가 폭주하는 치명적 결함** 발견.
- **만료 30초 선제 판독 로직 도입**: 프론트엔드에서 JWT 페이로드의 `exp` 값을 디코딩하여 만료 30초 전에 선제 판정(`isAdminTokenExpired`)하는 로직 구현. 
- **View 강제 전환(Force Relogin)**: 에러가 나기 전에 토큰을 선제 삭제하고 `minchodan:admin-auth-expired` 커스텀 이벤트를 발행하여 **사용자 UI를 로그인 창으로 즉시 강제 복귀**시키도록 처리. 콘솔 크래시와 서버 에러 과부하 문제를 100% 해소.

## 3. 부가 세부 구현 내용

### 3-A. 1단계 WebSocket 뼈대 및 3단계 반사 게이트 하드코딩
- **WebSocket 라우터 구성**: `ws_router.py`에 세션 인증, 하트비트, 프레임 수신 및 Redis Streams(`risk.events`) 발행에 이르는 1단계 관문 로직 구축.
- **Reflex Gate 고도화**: 시각장애인에게 치명적인 5대 돌발/동적 장애물(차량, 트럭, 버스, 오토바이, 킥보드)을 식별하는 하드코드 로직 구현. **BBox 회랑 띠(Corridor) 침범 기반**으로 거리에 따라 정면 판정 폭을 동적으로 좁히거나 넓혀 탐지 정확도 향상.

### 3-B. STT Whisper 런타임 크래시 폴백 및 한글 숫자 연락처 저장
- **Whisper CPU/CUDA 동적 폴백**: GPU 컨테이너 내에서 `libcublas.so.12` 누락 등으로 인해 CUDA 인코딩(`float16`) 런타임 에러(`RuntimeError`)가 발생할 경우, 서버가 죽지 않고 즉각 `int8` CPU 모델로 캐시를 갈아끼우며 1회 재시도(Fallback) 하도록 방어 코드 구현. (발화 15초 기준 STT 전사 지연: CUDA 0.11초 ↔ CPU 16초 간의 부하 스위칭 성공)
- **한글 숫자 전화번호 전사 대응**: STT가 "공일공일이삼사"와 같이 숫자를 한글로 전사하여 정규식을 통과하지 못하는 버그 대응. 한글 연속 문자를 추출해 아라비아 숫자로 치환하고 유효 길이와 앞자리(`01`)를 검증하는 2중 폴백(`_find_korean_spoken_phone`) 설계 적용.

### 3-C. GilDang_DB 및 Redis 통합 헬스체크 진단 스크립트
- **통합 상태 모니터링**: 프로젝트 DB 분리로 신설된 `GilDang_DB`(MariaDB)와 Redis, 그리고 원격 실기기 접속을 위한 Tailscale Daemon의 가동 상태를 비동기로 동시 PING 진단하는 `check_services.py` 스크립트 작성. 시연 및 개발 전 인프라 상태를 5초 이내에 원클릭으로 점검하도록 효율화.
- **더미데이터 시딩 자동화**: `Minchodan_DB_Clone.sql` 및 `seed_dummy_data.sql`을 작성해 테스트 환경(관리자 계정, 앱 유저, dev-001 디바이스)에서 원클릭 DB 프로비저닝이 가능하게 구성.

## 4. 문제 해결 과정 (Troubleshooting)

### 4-A. 불균형 클래스 모델 성능 저하 극복 (FiftyOne API)
- **문제 발생**: 일상 주행 및 보행 데이터 특성상, 차량이나 사람 클래스는 과도하게 많고 전동 킥보드, 볼라드와 같은 위험 객체의 데이터가 현저히 적어 탐지율이 저하되는 문제 발생.
- **원인 분석**: YOLO 학습 시 다수 클래스에 편향되어 소수 클래스의 Gradient가 희석되는 전형적인 Class Imbalance 문제로 확인.
- **해결 방안**: 파이썬 환경에서 **FiftyOne API**를 통해 소수 클래스 조건부 쿼리를 돌려 관련 데이터만 집중적으로 마이닝 및 증강했습니다. 이를 파인튜닝 학습 데이터셋에 병합함으로써 미탐지를 방어하고 위험 객체 mAP 수치를 끌어올렸습니다.

### 4-B. 추적기 공유로 인한 반사 경로 "튐" 및 중복 경보 방지
- **문제 발생**: 실기기 테스트 중 Medium 영역에 있던 객체가 Near로 근접 시 햅틱/비프가 울리지 않고 끊기거나 안내가 중복 송출.
- **원인 분석**: 8fps(반사 스트림)와 2fps(인지 스트림)가 단일 `ByteTrack` 인스턴스를 공유하면서 추론 스레드풀에서 동시 실행되어 ID 튐(track_id 리셋) 현상 발생. 이로 인해 위험 누적 카운트(`hit_count >= 3`) 조건이 무효화됨.
- **해결 방안**: 파이프라인을 스트림별로 완전히 분리. Redis 트랙 컨텍스트 키 또한 `ctx:{stream}:{track_id}` 형태의 네임스페이스로 분리하여 교차 오염을 원천 차단. 

### 4-C. STT RAG의 도메인 시프트(Domain Shift) 극복 노력
- **문제 발생**: 실외 보행 데이터(AI Hub)로만 학습된 가중치로 인해, 실내 데모 시연 시 천장의 무늬나 조명을 하늘(Sky)이나 차량(Car)으로 오분류하는 등 신뢰도가 급감하는 현상 관찰.
- **해결 방안**: 임시로 씬 분류기(Scene Classification) 및 실외 노면 `co-occurrence` 필터를 연계하여 실내 오탐을 완화. 궁극적인 해결을 위해 다양한 환경 데이터를 확보하여 파인튜닝하는 방안을 후속 계획으로 도출.

## 5. 프로젝트 평가 및 개선 방향

### 프로젝트의 성과
- 단순한 API 연동이나 추론 테스트를 넘어, FiftyOne API를 연동해 직접 불균형 데이터를 마이닝하고 **35만 장 규모의 파인튜닝 데이터셋**을 엮어 RTX 5090 기반 대규모 모델 학습 파이프라인을 구축하는 등, 완전한 AI 딥러닝 라이프사이클 엔지니어링을 수행했습니다.
- 백엔드 탐지 로그를 브라우저 환경에서 SSE로 안전하게(401 JWT 만료 방어) 처리함으로써, 무중단 실시간 관제 콘솔 개발의 아키텍처적 완성도를 높였습니다.
- 41개 시나리오 기반의 생활지원 RAG 시딩과 LLM 핫스왑 로직으로 예측 불가능한 돌발 상황에서도 시각장애인에게 안정적인 정보를 제공하는 뼈대를 만들었습니다.

### 향후 개선 계획
- **자동화된 프론트엔드 E2E 테스트 도입**: 로컬 백엔드/인프라 헬스체크(`check_services.py`) 스크립트는 고도화되었으나, React 프론트엔드 UI/UX 흐름을 보장하는 Cypress 등 브라우저 레벨의 E2E 테스트 자동화는 완수하지 못했습니다. 추후 이를 도입해 CI 신뢰도를 끌어올리고자 합니다.
- **개인화된 편의 기능 영속성 확보**: 연락처 저장이나 음성 긴급 전화 등 본 프로젝트에서 시도했던 편의 기능들을 RAM 기반 단발성 휘발 스토어(`ContactStore`)가 아닌 MariaDB(`GilDang_DB`) 유저 테이블에 영속화시켜 실서비스 관점의 UX로 발전시킬 여지가 있습니다.
