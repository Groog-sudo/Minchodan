# Minchodan 파이프라인 최종 보고서 (Final Report)

## 1. 프로젝트 요약
본 프로젝트는 시각장애인 보행 보조용 **YOLO 26n 모델**의 성능 고도화를 위해, 기존 COCO 및 OpenImages만으로는 확보가 불가능한 **한국형 보행 환경 장애물(키오스크, 볼라드, 점자블록, 파손 노면 등)** 데이터를 구축하기 위한 자동화 파이프라인(Miner)을 개발하는 것이었습니다.

## 2. 파이프라인 아키텍처 및 주요 성과
1. **모듈형 파이프라인 구성:** 
   - `miners/aihub_objdet_miner.py` (Object Detection 지원)
   - `miners/aihub_seg_miner.py` (Segmentation 지원)
   - 스크립트 실행 시 pHash 알고리즘을 통한 이미지 중복 방지.
2. **이종 데이터 스키마 통합:** 
   - AI Hub의 파편화된 데이터 포맷(일반 JSON, Bounding Box JSON, CVAT XML, Polygon JSON)을 모두 파싱할 수 있는 로직 구현.
3. **학습-레디(Training-Ready) 포맷 변환:** 
   - 추출된 모든 좌표 데이터를 YOLO의 0~1 정규화 포맷(`txt`)으로 완벽히 자동 변환.
4. **검증 도구 제공:** 
   - `utils/visualize_samples.py`를 통해 변환된 라벨이 이미지 상에 정확히 안착하는지 개발자가 즉각 확인할 수 있는 시각화 환경 제공.

## 3. 한계점 및 도메인 맞춤 해결책 (RAG / TTS 연계)
AI Hub 원본 데이터의 라벨링 한계(예: '대차(구루마)'가 독립 클래스가 아닌 'carrier'로 묶여 있거나 누락됨)가 확인되었습니다. 
하지만 보행 보조 도메인의 관점에서 바퀴 달린 이동형 화물(대차, 캐리어)은 동일한 회피 대상입니다. 따라서 별도의 클래스 분리(Over-engineering)를 진행하지 않고 **`carrier` 클래스로 포괄하여 예측**한 뒤, 후속 RAG(검색 증강 생성)나 LLM 판단 모델, 혹은 TTS 안내 시 **"전방에 캐리어나 대차 같은 이동형 장애물이 있습니다"**라고 통합 안내하는 아키텍처 결정을 내렸습니다.

## 4. 향후 활용 방안 (Next Steps)
현재 작업 공간에 마련된 도구(`obstacle_data_miner`)를 사용하면, 향후 1TB 단위의 AI Hub 압축 파일을 다운로드 받아도 명령어 한두 줄로 모델 학습용 데이터셋 정제 과정이 전자동으로 이루어집니다. 
데이터 정제 환경이 모두 완성되었으므로, **대용량 파싱 -> 모델 파인튜닝(Fine-Tuning)** 단계로 즉각 돌입이 가능합니다.
